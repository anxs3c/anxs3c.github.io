Overview: Access control vulnerabilities (also known as authorization flaws) occur when an application fails to properly enforce restrictions on what authenticated users are allowed to do. These labs demonstrate various privilege escalation techniques including:
  • Horizontal Privilege Escalation — Accessing another user's data
  • Vertical Privilege Escalation — Gaining administrative privileges
  • IDOR (Insecure Direct Object References) — Accessing unauthorized resources
  • Access Control Bypass — Circumventing authorization checks

Lab 2: Unprotected Admin Functionality with Unpredictable URL

Lab Description:
This lab has an unprotected admin panel at an unpredictable location.
Goal: Delete the user carlos.

How was the lab compromised?

I first checked the /robots.txt file, but it returned a 404 Not Found response. I then analyzed the page source and discovered a client-side JavaScript snippet: 

<script>
  var isAdmin = false;
  if (isAdmin) {
     var topLinksTag = document.getElementsByClassName("top-links")[0];
     var adminPanelTag = document.createElement('a');
     adminPanelTag.setAttribute('href', '/admin-76g9xu');
     adminPanelTag.innerText = 'Admin panel';
     topLinksTag.append(adminPanelTag);
  }
</script>

The script revealed the admin panel URL: /admin-76g9xu. Even though the isAdmin variable was set to false, the link to the admin panel was hardcoded, allowing me to directly access the endpoint.

Lab 2 Solved! Admin URL discovered in client-side JavaScript.

Lab 9: Insecure Direct Object References

Lab Description:
User chat logs stored directly on the file system, retrieved using static URLs.
Goal: Find the password for carlos and log into their account.

How was the lab compromised?

I tested the live chat functionality and clicked on "View Transcript". The application exported a file named 2.txt.

I intercepted the request and modified the filename parameter to 1.txt, which gave me access to unauthorized chat logs containing the password.

Vulnerability Analysis:
The application stores chat logs directly on the server as text files and makes them accessible via static URLs (1.txt, 2.txt, etc.). The application does not verify whether a user is authorized to access these files, allowing an attacker to modify the filename and access other users' chat logs.
Lab 9 Solved! IDOR on chat log files.

Insights & Security Mitigations

Never rely on client-side checks for authorization
Best Practices:
  • Always enforce role validation on the server side
  • Do not trust user-controlled parameters: id, role, username, etc.
  • Protect administrative endpoints with proper authentication and authorization controls
  • Avoid exposing sensitive data in redirects or HTTP responses
  • Validate HTTP methods and security-related headers appropriately
  • Implement object-level authorization checks to prevent IDOR/BOLA vulnerabilities
  • Enforce server-side access control checks for every request
  • Implement role-based access control (RBAC) correctly
  • Validate resource ownership before returning sensitive data
  • Avoid predictable identifiers; use random or non-sequential IDs where possible
  • Do not expose administrative endpoints in client-side code
  • Restrict direct access to sensitive URLs
  • Log and monitor privilege escalation attempts
Conclusion:
These labs demonstrate how Broken Access Control vulnerabilities can arise from improper authorization checks, client-side trust, and insecure handling of user-controlled input. By manipulating parameters, modifying cookies, bypassing front-end restrictions, and exploiting flawed access control logic, it was possible to escalate privileges, access sensitive data, and perform administrative actions without proper authorization.
